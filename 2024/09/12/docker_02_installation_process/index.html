1 安装环境简介

因为阿里云服务器已经服役于本网站，对于本次安装使用VMware Workstation Pro 17的虚拟机，宿主机为win11专业版，虚拟机环境为Ubuntu 24.04.1 LTS 。

2 关于虚拟机的安装

因为时间有些久了，考虑到需要复健K8S，所以选择了Ubuntu 22.04 Jammy Jellyfish 桌面版（ https://ubuntu.com/download/desktop），它有足够新的特性，非常适合运行Kubernetes，而内置的浏览器、终端等工具也很方便我们的调试和测试。

我使用了win11作为宿主机，但对Apple M1用户来说，有一个不太好的消息，Ubuntu 22.04在内核由5.13升级到5.15的时候引入了一个小Bug，导致VMWare Fusion无法正常安装启动，这个问题直到4月份的正式版发布还没有解决。

虚拟机网络设置

点击”编辑“，点击”虚拟网络编辑器“，点击”虚拟网络编辑器“中的”更改设置“。

这里有三种模式，分别是桥接模式、仅主机模式、NAT模式。

  • 桥接模式：虚拟机的虚拟网络适配器与主机的物理网络适配器进行交接，虚拟机中的虚拟网络适配器可通过主机中的物理网络适配器直接访问到外部网络。
  • NAT模式： NAT 模式也是 VMware 创建虚拟机的默认网络连接模式 。使用NAT模式网络连接时，VMware会在主机上建立单独的专用网络，用以在主机和虚拟机之间相互通信。
  • 主机模式：比 NAT 模式更加封闭的的网络连接模式，它将创建完全包含在主机中的专用网络。

点击NAT设置，记下”子网IP“、”子网掩码“和”网关IP“，此处后续需要使用。

新建虚拟机

点击”文件“，选择”新建虚拟机“，在弹出的”新建虚拟机向导“，选择”经典“，选择”下一步“。

选择安装程序光盘映像文件，选中下载的unbuntu，点击”下一步“。

输入对应的信息，这里我输入的用户名li，密码是123456

修改虚拟机名称，选择存放位置，点击”下一步“。

这边我将最大磁盘大小调整到了40GB，也是考虑后续安装K8S，点击”下一步“。

这里选择”自定义硬件“。

在网络设备器选择”桥接模式“，这里如果选择NAT模式时，虚拟机创建后无法连接网络，可能会导致虚拟机开启后设置后因为无法连接网络无法启动或者登录卡住的问题。（这是我遇到的一个问题，修改后解决了）。

因为我用不到蓝牙和声卡，我就都关闭了。

在”显示器“设置中，关闭”加速3D图形“，开启时有可能导致虚拟机卡顿甚至黑屏。

最后点击完成。

出现上述提示时去虚拟机设置高级中关闭即可，未关闭可能会导致虚拟机卡顿甚至黑屏。

进入虚拟机后点击设置中的网络，将有限网络修改为手动，掩码、网关设置为NAT中对应设置，IP设置为该网段即可，比如我设置为了192.168.239.130。

此时修改虚拟机设置，将网络切换为NAT，ping下百度等保证通畅。

到此我们虚拟机网络就设置好了！

3 安装方便操作的软件并使用ssh连接虚拟机

接下来我们将在虚拟机安装一些用于操作的软件。

安装ssh，修改密码设置

快捷键ctrl+shift+T呼出终端，我们先修改一下root密码，并且切换到root用户

按照要求依次输入当前用户密码，root密码，确认root密码即可。接下来我们使用下述切换至root用户并且安装ssh。

上图为ssh正常启动，因为习惯使用vim，unbuntu老用户仍旧可以使用nano等，我使用”sudo apt install vim“安装了vim。

在修改root用户密码时，我们可能会遇到如”密码未通过字典检查 - 过于简单化/系统化“报错。因为是虚拟机，我们便于登录管理修改等，这里可以去修改一下设置。

基于 DEB 的操作系统中，密码和身份认证相关的配置文件被存储在 /etc/pam.d/ 目录中，我添加了 minlen=6 由此设置了密码最小长度为6，随后我将root密码修改为123456。

使用ssh登录机器

可以使用类似xshell、MobaXterm等软件ssh登录到虚拟机了！

这里我使用了MobaXterm，点击会话，输入虚拟机设置时的ip，输入指定用户进行点击确定。随后可以直接连接时会要求输入密码。

有些朋友可能疑惑这里为什么不适用root直接登录，ssh默认是未开启root登录的，修改可以通过 sudo vim /etc/ssh/sshd_config 在文件中写入或者放开 PermitRootLogin yes ，重启ssh服务，此后便可使用root登录啦。

看到下面的界面就证明成功啦！

Docker Engine不像Docker Desktop那样可以安装后就直接使用，必须要做一些手工调整才能用起来，所以你还要在安装完毕后执行下面的两条命令：

第一个 service docker start 是启动Docker的后台服务，第二个 usermod -aG 是把当前的用户加入Docker的用户组。这是因为操作Docker必须要有root权限，而直接使用root用户不够安全， 加入Docker用户组是一个比较好的选择，这也是Docker官方推荐的做法。当然，如果只是为了图省事，你也可以直接切换到root用户来操作Docker。

上面的三条命令执行完之后，我们还需要退出系统（命令 exit ），再重新登录一次，这样才能让修改用户组的命令 usermod 生效。

现在我们就可以来验证Docker是否安装成功了，使用的命令是 docker version 和 docker info。

docker version 会输出Docker客户端和服务器各自的版本信息：

docker info 会显示当前Docker系统相关的信息，例如CPU、内存、容器数量、镜像数量、容器运行时、存储文件系统等等
