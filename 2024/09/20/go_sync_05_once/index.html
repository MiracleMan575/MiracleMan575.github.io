Once 可以用来执行且仅仅执行一次动作，常常用于单例对象的初始化场景。

使用

Once 只有一个 Do 方法，接受一个无参数的 func() ，保证多次调用 func() 只被执行一次。我来写一个例子，我们用之前的知识生成10个 goroutine 并在 goroutine 内调用一个 Work 函数。只不过我们使用 Once.Do(f) 进行调用。

可以看到我们虽然调用了10次 Work ，但真正被执行的只有一次。

原理

数据结构

Once的数据结构只有两个字段组成，分别是：

  • done：标记是否已经执行
  • m：互斥锁

方法实现

我们直接看 Do 方法，直接判断了 done 字段是否为0，如果不是，那代表函数已经被执行，直接返回；是0则进入 doSlow。

func (o *Once) Do(f func()) {

if atomic.LoadUint32(&o.done) == 0 {

o.doSlow(f)

}

}

在 doSlow 中，首先加锁，再对 done 字段进行了双重检查。如果还是为0则执行 f() 函数，并在执行后通过原子操作将 done 置为1。

上面说需要对 done 字段进行双重检查，这里说下必要性。首先，在判断好 done 字段是否为0到获取到互斥锁是有一段时间的，函数返回可能发生在这之间。如下图 g1 和 g2 同时执行了 Do 方法，都进入 doSlow ，并一起竞争锁， g1 获取到锁后， g2 会阻塞， g1 执行 f() 后将 done 置为1，此时 g2 获取到锁，如果没有检查，这时 g2 会再次执行 f() ，这造成了浪费和违背了 Once 真正被执行的只有一次的原则。如果加入了第二次检查， g2 会再次判断 done 字段是否为0，由于 g1 将 done 置为1，所以 g2 会直接返回。

题外话

关于内联

已经学习了几个并发原语的实现，你可能注意到总是有些 slowXXXX 的方法，从 XXXX 方法中单独抽取出来，这么做是为什么呢？风格？易读？答案是内联。

内联优化是一种常见的编译器优化策略，通俗来讲，就是把函数在它被调用的地方展开，这样可以减少函数调用所带来的开销(栈的创建、参数的拷贝等)。

那什么样的函数会被内联呢？

  • 函数足够简单，当解析AST时，Go申请了80个节点作为内联的预算。每个节点都会消耗一个预算。函数的开销不能超过这个预算；
  • 不能包含闭包，defer，recover，select；
  • 不能以 go:noinline 或 go:unitptrescapes 开头；
  • 必须有函数体；
  • 其他等复杂要求，详细可见src/cmd/compile/internal/gc/inl.go相关内容。我们可以使用 gcflags 参数来判断能不能内联。
