帮助命令

镜像命令

docker images

执行该指令之后，信息显示如上图所示，对每个标签的解释如下：

  • REPOSITORY 镜像的仓库源（也就是镜像名 ）
  • TAG 镜像的标签（也就是镜像的版本，如果不指定，则默认为lastest，也就是最新版）
  • IMAGE ID 镜像的ID（同一个镜像的不同版本，拥有不同的镜像ID）
  • CREATED 镜像的创建时间
  • SIZE 镜像的大小

我们通过 docker images --help 具体看下指令的可选项：

docker search

  • NAME # 镜像名
  • DESCRIPTION # 镜像描述
  • STARS # 收藏数（类似于GitHub上的STARS，STARS越多，表示越受欢迎，下载次数越多）

老样子我们还是使用 docker search --help 具体看下相关可选参数

使用以下几种方式均可

docker search --filter=stars=5000 mysql docker search --filter stars=5000 mysql docker search -f=stars=5000 mysql docker search -f stars=5000 mysql

比如我们筛选除了stars不小于5000的mysql镜像。

docker pull

docker rmi

删除镜像，我们照例help看看命令

容器命令

有镜像才能创建容器，我们这里使用centos的镜像来测试，就可以先通过通过 docker pull centos 拉取以下centos镜像。

新建容器并启动（docker run）

docker run 就是 docker create 和 docker start 结合体。老样子help一下，可以看到很多可选参数，这里挑几个用的频率高的来看下。

我们尝试使用 docker run -it centos /bin/bash 启动一个centos。

可以看到已经进入容器内部了。

退出容器（exit、Ctrl+P+Q）

退出容器有两种方式，

我们可以先采用exit退出，通过docker ps查看是否运行，重新使用 docker run -it centos /bin/bash 启动一个centos。

可以看到已经没有在运行的容器了，我们尝试使用Ctrl+P+Q退出容器。

可以看到我们创建的id为c795a292febc的容器还在运行。

列出所有运行的容器（docker ps）

我们可以通过 docker ps 命令查看所有运行的容器。我们使用help看下具体参数。

启动 / 停止容器（docker start、docker restart、docker stop、docker kill）

这里我们可以依次运行一下 docker stop、 docker start、 docker restart 以及 docker kill，每个命令后使用 docker ps 观察一下容器的运行情况。

删除容器（docker rm）

我们先使用 docker run 命令尝试创建三个容器，每个容器创建后都使用Ctrl+P+Q退出。

我们尝试删除ID为860开头的容器：

可以观察到我们收到了一个错误，原因是容器并未停止。所以我们需要先使用 docker stop 停止我们要删除的容器，再删除该容器，随后我们可以通过 docker ps -a 命令确认容器是否被删除。

接下来我们使用 docker rm -f $(docker ps -aq) 删除所有容器，不要忘记先停止容器哦。同样我们通过其他命令辅助查看是否被全部删除。

可以看到容器已经被都删除了。

常用其他命令

后台启动容器（-d）

我们可以通过 docker run -d centos 后台启动一个centos容器

上图有些小伙伴可能会有疑问，因为我们使用 docker ps 查看运行容器列表时并未显示，这是因为Docker容器后台运行，就必须有一个前台进程，容器运行的命令如果不是那些一直挂起的命令，就会自动退出。

我们可以尝试再做一个实验，我们使用 docker run -d centos /bin/sh -c "while true;do echo hello;sleep 5;done" 启动centos镜像，意思是让该容器运行一个每隔5秒就输出一边hello的死循环前台程序。

我们可以看到因为有了前台程序，该容器被创建并且运行。所以对于该命令，一般适合具有前台程序的镜像如tomcat。

查看日志（docker logs）

我们可以使用该命令查看容器输入的日志。

查看容器中运行的进程信息（docker top）

查看容器 / 镜像的元数据（docker inspect）

进入正在运行的容器（docker exec、docker attach）

docker exec

我们通过help查看一下选用参数

我重新创建了一个容器并使用 docker exec -it 806 /bin/bash 进入了容器，这里是新开了一个交互窗口，是跟之前创建容器时的窗口是并行的，所以此时我们使用 exit 不会停止该容器运行。

还记得我们之前使用过的为了保持前台进程而使用的死循环容器么？我们启动容器并使用exec进入容器时，会发现并没有死循环的输出hello，这也印证了使用exec -it时开启了一个新的交互窗口，exit同样退出的是这个交互窗口，我们通过logs命令可以看到该容器还在运行每隔5秒输出hello的脚本。

docker attach

attach命令同样是进入容器，但attach是将后台命令置到前台，所以打开的应该是跟挂在后台的同一个交互窗口，即如果容器只有一个交互窗口，使用exit时会导致容器退出。

由此，两者虽同样都可以进入容器，但有以下区别：

区别

  • exec：容器中打开新的终端，并且可以启动新的进程
  • attach：进入容器挂在后台的终端，不可以启动新进程

从容器内拷贝文件到主机上（docker cp）

我们新建一个centos容器在其中 /home 中新建 xiaoli.go，我们使用CTRL+P+Q退出容器，使用docker cp命令即可将容器内数据拷贝到本机，当然这个容器是否停止没有关系，容器只要创建了，停止时数据也仍旧是在的，除非删除容器才可能导致数据丢失。
