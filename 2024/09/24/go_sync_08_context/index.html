Go并发8——Context

context 是 golang 中的经典工具，主要在异步场景中用于实现并发协调以及对 goroutine 的生命周期控制。

使用

我们写了一个例子，实现了一个带有取消功能的 context ，并在 goroutine 工作时对 context 进行取消。

数据结构

Context 为 interface，定义了四个核心 api：

  • Deadline：返回 context 的过期时间；
  • Done：返回 context 中的 channel；
  • Err：返回错误；
  • Value：返回 context 中的对应 key 的值.

emptyCtx

  • emptyCtx： 是一个空的 context，本质上类型为一个整型；
  • Deadline： 方法会返回一个公元元年时间以及 false 的 flag，标识当前 context 不存在过期时间；
  • Done： 方法返回一个 nil 值，用户无论往 nil 中写入或者读取数据，均会陷入阻塞；
  • Err： 方法返回的错误永远为 nil；
  • Value： 方法返回的 value 同样永远为 nil。

context.Background() & context.TODO()

我们所常用的 context.Background() 和 context.TODO() 方法返回的均是 emptyCtx 类型的一个实例。

除了上面两个常用的生成Context的方法，还提供了四个生成特殊的Context的方法，分别时WithValue、WithCancel、WithDeadline、WithTimeout。

  • WithValue 方法其实创建了一个 ValueCtx 类型的 Context，并保存一个kv键值对，用于传递上下文信息，以及持有父 context，它覆盖了 value 方法，并实现了链式查找，当查找键值对时，会优先从自身的存储中查找 key，如果没有则会从父 context 中查找。
  • WithCancel 返回一个 CancelCtx 以及一个 cancel 函数，通常应在一些需要主动取消长时间任务的情形。使用方法是创建这种 Context，然后把这个 Context 传递给长时间执行任务的 Goroutine，当需要终止任务的时候，可以调用 cancel 函数，这样就可以通知父 goroutine 子 goroutine 已经取消执行了。需要注意的是 cancel 函数一定要尽早释放。 cancel 方法是向下传递的，当父 Goroutine 被 cancel 时，子 Goroutine 如果也是 CancelCtx 类型的话也会被 cancel，但是它不能向上传递。当 cancel 调用时，Err方法会返回一个 context canceled 错误。
  • WithTimeout 就是调用了 WithDeadline，只不过一个是设置了超时时间，一个是设置了截止时间。
  • Withdeadline 返回一个 TimeCtx 或者 CancelCtx，并设置一个截止时间，如果该时间超过了父 Ctx 的时间那么就以父 ctx 为准，并返回一个 CancelCtx；如果当前时间已经超过截止时间，那么会直接返回一个已经被 cancel 的 TimeCtx，否则就会启动一个定时器，到截止时间的时候就取消这个 TimeCtx。
