接下来我们运用前面学到的几个命令尝试部署一下常用软件。

我们先来思考一下，我们要部署一个容器，肯定需要经过镜像的查找和拉取，对应 docker search 及 docker pull，此后需要创建运行容器，就是 docker run，然后通过 docker ps 检查一下容器是否已经运行即可。

部署nginx

同样我们可以在宿主机上访问虚拟机 ip:3344，同样可以访问，如果是服务器，像阿里云通过安全组同时os放开对应端口，公网就可以访问了。

之后我们就可以进入nginx修改配置啦。 但每次我们更改配置文件，得要进入nginx容器中修改。

部署tomcat

同样的方法即可进行部署，这里不作过多描述，将端口改为容器8080映射至本机某个开放端口即可。但如nginx，tomcat我们每次部署项目都要进入容器中，是否有些麻烦呢？

部署ES+Kibana

ES

相对于前面不同，ES需要开放多端口并且很耗内存，同时需要挂载数据卷。接下来我们尝试去安装一下ES并解决一下上述问题。

使用 docker stats 查看使用内存可发现es非常耗内存，几乎占用了我们虚拟机2个G的内存，如果是在学生版阿里云服务器可能就宕机了。

但是如果我们的环境就是这么低配，难道ES就不可用了么？

其实我们可以限制其内存，使用下述命令启动，限制ES最小内存64M最大512M。启动后我们查看下内存占用。

可以看到内存占用224M，同时ES也是可用的。

Kibana

Kibana是连接ES的，所以需要通过网络访问，但是容器之间是相互隔离的，所以Kibana是无法直接连接ES的，我们很容易想到可以通过本机内网ip转发的形式，这里就需要网络设置啦！
