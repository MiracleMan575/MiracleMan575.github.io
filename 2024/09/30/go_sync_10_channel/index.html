“不要通过共享内存来通信，而要通过通信来共享内存”。

与主流语言通过共享内存来通信进行并发控制的方式不同， Go 语言的并发模型采用了 CSP 模式， goroutine 之间使用共享的 channel 进行通信，通过通信传递数据。

使用

引用类型，空值是nil。声明后的channel需要使用make函数初始化。

channel操作

有发送（ send）、接收( receive）和关闭（ close）三种操作。

关闭使用 close(ch1)

  • 对一个关闭的通道再发送值就会导致 panic。
  • 对一个关闭的通道进行接收会一直获取值直到通道为空。
  • 对一个关闭的并且没有值的通道执行接收操作会得到对应类型的零值。
  • 关闭一个已经关闭的通道会导致 panic。

数据结构

hchan（channel）

  • qcount：当前 channel 中元素个数
  • dataqsiz： channel 最多可存放的元素个数
  • buf： channel 环形队列数组
  • elemsize： channel 每个元素的大小
  • closed：标识 channel 是否关闭
  • elemtype： channel 元素类型
  • sendx：写下标
  • recvx：读下标
  • recvq：等待读的 goroutine 队列，对应 waitq
  • sendq：等待写的 gouroutine 队列，对应 waitq
  • lock：互斥锁

waitq（recvq/sendq）

  • first：队列头部
  • last：队列尾部

sudog（包装协程的节点）

  • g： goroutine，协程；
  • next：队列中的下一个节点；
  • prev：队列中的前一个节点；
  • elem: 读取/写入 channel 的数据的容器;
  • isSelect：标识当前协程是否处在 select 多路复用的流程中；
  • c：标识与当前 sudog 交互的 chan.

构造器及读写流程

构造器

根据不同类型，我们 make channel 时会发生以下三种情况：

  • 无缓冲型
  • 有缓冲的 struct 型
  • 有缓冲的 pointer 型

我们直接看 makechan 方法，首先我们根据元素类型和长度计算出 channel 的大小，判断超限，随后进入switch：

  • mem == 0：无缓冲的类型或缓冲区元素为 struct，默认分配 hchanSize 大小的空间；
  • elem.ptrdata == 0：有缓冲的 struct 型，一次性分配好 hchanSize + mem 大小的空间，并且调整 chan 的 buf 指向 mem 的起始位置；
  • default：有缓冲的 pointer 型，则分别申请 chan 和 buf 的空间，无需连续。

写流程

写流程大体入上图，其中写流程会调用 func chansend1(c *hchan, elem unsafe.Pointer)，内部直接调用了 chansend(c, elem, true, getcallerpc())。

  • c 表示操作的 channel
  • ep 是一个指针，指向发送的数据 ch <- i
  • block 表示是否是阻塞调用，在 select case 语句中才会设置为 false

我们看详细代码，从上图中我们可以看到我们首先判断了未声明的情况， channel 若为 nil 会触发 gopark 永久挂起，因为我们无法从此 channel 中取数据，所以就变成了死锁。

在 channel 加锁之前，对于非阻塞并且未关闭的情况会有一步快速检测的判断，我们可以看到之前学习的并发原语中都有这种快捷路径。

此后进行加锁并判断 channel 是否已经关闭，关闭则解锁并触发 panic；

如果待接受队列中有等待的接收者，则说明缓冲区是空的，则可直接从接手队列中取 goroutine 并将数据直接 copy，这里在 send 中就直接进行了解锁；

若缓冲区未满，则直接将数据发送到缓冲区；

channel 未关闭，对于非缓冲 channel，待接收队列为空，对于缓冲 channel，缓冲区已满：非阻塞的话，会直接返回为发送成功；阻塞调用，则会构建 sudog 对象，然后添加到待发送队列，解锁，挂起当前 goroutine

会被唤醒的情况有两种

  • 关闭 channel
  • 发生接收操作，接收者可能会唤醒该发送者

读流程

这里为了讲解方便把非阻塞代码剔除，大体流程如下。

根据我们读方式不同，可以分成两种情况，但底层都是调用了一个方法。其中 chanrecv1 是直接进行读，而 chanrecv2 则返回了 bool 值。

我们直接看 chanrecv 内部，和写操作一样，读流程也会检查未声明情况： channel 若为 nil 会触发 gopark 永久挂起，造成死锁。

加锁判断 channel 是否已经关闭，关闭判断是否还有剩余元素，没有时进行解锁并输出元素零值返回 false；

待发送队列不为空，存在待发送者：如果待发送队列中有等待发送的 goroutine，说明 channel 是非缓冲channel，或者缓冲区已经满了;

  • 非缓冲channel，会将数据从待发送者复制给接收者
  • 缓冲区已满的话，会先从缓冲区中接收数据，然后将待发送者的数据发送到缓冲区中

缓冲区中有数据，无论 channel 被关闭，都会发送给接收者：

  • 获取缓冲区的待接收数据的地址 gp，如果有接收者，便将数据复制给接收者
  • 调整缓冲区循环数据的待接收索引 recvx

channel 未关闭， 缓冲区没有元素，并且没有待接收者 ：挂起当前 goroutine，等待被发送操作或者关闭操作唤醒。
