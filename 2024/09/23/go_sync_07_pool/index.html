sync.Pool 标准库下并发安全的对象池，适合用于有大量对象资源会存在被反复构造和回收的场景，可缓存资源进行复用，以提高性能并减轻 GC 压力。

Pool的优势

这里请允许我先简述一下一点前置知识。

gc

go 使用三色标记法和混合写屏障进行垃圾回收，旨在将无引用的对象从内存中回收，释放资源。

gmp

g： goroutine；

m：类比内核线程；

p：调取器，通常 p 的数量等于 cpu 核数。

  • p 为中枢，m 通过与 p 的结合，调度 g；
  • p 有本地 g 队列和全局 g 队列，前者取 g 不加锁，后者加锁；
  • 抢占式调度， g 因为阻塞或者时间片耗尽，可能回到等待队列，最终前后可能被不同的 g 和 m 执行。

pool

pool 的作用就是防止对象资源会存在被反复构造和回收。那具体是怎么做的呢？

使用

数据结构

  • noCopy：防拷贝标识；
  • local：类型为 [P]poolLocal 的数组，数组容量 P 为 goroutine 处理器 P 的个数；
  • victim：经过一轮 gc 回收，暂存的上一轮 local；
  • New：为用户指定的工厂函数，当 Pool 内存量元素不足时，会调用该函数构造新的元素。
  • p oolLocal：为 Pool 中对应于某个 P 的缓存数据；
  • private：对应于某个 P 的私有元素，操作时无需加锁；
  • shared： 某个 P 下的共享元素链表，由于各 P 都有可能访问，因此需要加锁.

方法实现

Pool.Get()

思路大体为通过 pin 绑定 p 和 gorountine，尝试获取无需加锁 private，获取不到时获取需要加锁的 shared，若还是获取不到则从 victim 即上一轮 local 去获取 private/ shared，都获取不到时使用 New() 兜底。

pin

保持抢占 p，在 pin() 中没有绑定到 p，就通过 pinSlow() 加 互斥锁 获取 p，其中也涉及一些 poolLocal 的新建。

Pool.Put()

基本思路与拿取一致， pin 绑定 p 和 gorountine，优先放归还到 private 中，如果 private 有值，则放到 shared 中。

注意事项

  • 短生命周期的对象不太适合放对象池中
  • 对象池不要复制
  • 一般的使用场景，先声明 New()，然后再去使用 Get()/Put() 方法，可以 put 任何对象，但在 get 对象的时候，需要用到断言，即 Get().(Type)
  • 对象池中的对象数量不能做任何假设，什么时候新建什么时候被 GC，这些都是不确定的，对象池主要是能尽可能复用对象，减少 GC
  • Pool 本身的数据结构是并发安全，但是 Pool.New() 方法需要使用者注意场景使用，如并发下，则加上并发安全策略，如原子操作或者加互斥锁等
