1 镜像加载原理及讲解

什么是镜像

镜像（Image）是一个轻量级、独立的可执行软件包，它包含了运行某个应用程序或服务所需的所有内容：代码、运行时环境、系统工具、系统库以及设置。

Docker镜像是Docker技术的核心之一，它允许开发者打包应用及其依赖，从而可以在 任何地方一致地部署 和运行这些应用。

镜像加载原理及联合文件系统

UnionFS（联合文件系统）

UnionFS（联合文件系统）是一种特殊的文件系统服务，它允许多个目录或文件系统的挂载点以一种透明的方式合并在一起，形成一个单一的目录层次结构。

支持对文件系统的修改作为一次提交来一层层的叠加，同时可以将不同目录挂载到同一个虚拟文件系统下。Union文件系统是docker镜像的基础。镜像可以通过分层来进行继承，基于基础镜像，可以制作各种具体镜像。

docker镜像加载原理

docker镜像实际由一层层文件系统组成，我们拉取镜像时也是一层层下载的。

如下图，docker底层基于了宿主机的内核，而获取的基础镜像也只是linux发行版中的一些命令集等等，所以对于我们使用docker拉取centos时，只有200多兆，但是我们看iso文件时却是几个G大小。同样的对于nginx，我们下载只需要几十兆，但拉取镜像时因为有着基础镜像及其依赖环境，我们发现nginx是100+兆。

当我们使用 docker inspect redis 时，可以看到他的 RootFS 中有一个 Layers，能看到镜像所有的层。

如果存在层相同，比如某应用软件基于centos最新版，我们拉取过centos最新版，那么可以直接复用从而不进行下载。

2 容器数据卷

什么是容器数据卷？

前面我们提起过，对于一个容器，我们删除时会导致内部信息丢失，但很多时候我们是需要将容器内信息持久化到磁盘上的。那么有没有一种方式，可以让容器内部的某些目录与宿主机目录相联系，或者自动的将其不断同步到宿主机呢？答案就是容器数据卷。

容器数据卷（Docker Volumes）是Docker中用于 持久化存储数据 的一种机制。与容器的生命周期不同，数据卷独立于容器的创建和销毁过程，这意味着即使容器被删除或重建，保存在数据卷中的数据仍然会被保留。数据卷提供了一种标准化的方式来管理非临时性的数据，如数据库文件、配置文件等。

我们使用 docker inspect 命令查看下容器，可以在 Mounts 下找到对应挂载。

卷挂载

数据卷挂载分为匿名挂载和具名挂载。

我们可以使用 docker volume 命令查看数据卷，通过help命令我们可以看到，我们可以通过 ls 查看已经存在的数据卷列表， create 新建数据卷， inspect 查看数据卷信息等等。

我们这里新建nginx容器，并在 -v 容器内地址，这样我们就实现了匿名挂载。

同样我们可以再启动一个nginx容器而使用 -v 卷名:容器内地址 实现具名挂载。在 docker volume ls 命令后可以观察到我们新建的挂载数据卷，名为nameNginx。且通过 docker volume inspect 命令可以具体查看到他被挂载到了宿主机的 /var/lib/docker/volumes/nameNginx/_data 目录下。

大多数情况下，在未指明目录情况下， 默认 都会挂载到宿主机 /var/lib/docker/volumes/?/_data 目录下，其中 ? 便是具体的数据卷名，所以推荐使用具名挂载。

当然，我们甚至可以通过 -v 卷名:容器路径:ro 或 -v 卷名:容器路径:rw 来控制是否只读或者可读可写等权限。对于ro代表只读即只能通过宿主机改变，而rw则是可读写。如下图，我们可以看到在 docker inspect 对应容器id命令的 Mounts 中对应也展示出容器数据卷的权限。

数据卷容器

数据卷容器是一种特殊的 Docker 容器，它主要用于数据的存储和共享。数据卷容器通常不运行任何应用程序，它的主要作用是提供一个可以被其他容器挂载的数据卷。这种模式的好处是可以在多个容器之间共享数据，并且即使创建了数据卷的原始容器停止或删除了，数据仍然存在。

通过数据卷容器，我们可以实现多个容器之间的数据共享。
